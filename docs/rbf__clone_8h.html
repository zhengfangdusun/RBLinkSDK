Detailed Description

Hub data import/export API (host validation; hardware validation pending).

Normal-mode callbacks execute on the clone worker (default stack: 64 KiB). Build the SDK with RBF_CLONE_THREAD_STACK_SIZE to override this budget. Keep callbacks bounded; use heap storage or an application queue for large work. The SDK schedules transfers internally. No application polling is required. Data is opaque: the application owns storage and file validation. This API does not promise selective import, merging, or simultaneous cloned hubs.

◆ rbf_clone_export_start()

int rbf_clone_export_start ( const RBF_clone_options_t *  options)

Request export mode; the HUB reboots. Requires initialized SDK, write/event callbacks and non-NULL valid options. SDK copies options before returning. Return 0 means accepted, not complete; -1 means rejected without starting. Concurrent clone or OTA sessions are rejected. With current firmware export completes automatically and preserves registered devices. Older firmware may clear the source; verify firmware compatibility before use. No DATA_READY/finish gate exists for export; await EXITED.

Import only: explicitly finish after DATA_READY. Export calls are rejected. The HUB validates completeness and exits normally or abnormally; there is no missing-chunk repair protocol. Wait for EXITED and inspect its reason. Returns 0 if accepted, -1 for invalid state or request failure.

◆ rbf_hub_factory_reset_recover()

int rbf_hub_factory_reset_recover ( void  )

Explicit recovery probe after factory-reset error/timeout only. Sends 60/00 (stop local enrollment); this also ends any active local enrollment session. Only a successful ACK confirms normal mode and emits EXITED/ABNORMAL while retaining the reset error (reset success remains unproven). A late successful 85 ACK instead emits EXITED/COMPLETED. Errors or missing ACK keep exclusion; call again to retry the non-destructive probe. Never resends factory reset. Returns 0 when queued, -1 for wrong state, pending probe or callback reentry.

Explicit destructive factory reset (0x85). reboot is 0 or 1; invalid values are rejected. Requires event callback and options; shares clone/OTA exclusion. Return 0 means queued, not complete. No automatic retry. EXITED/COMPLETED means a successful HUB ACK, not proof of reboot or erased device inventory; verify these separately after the operation. Errors/timeouts use clone status. Cancellation is not supported once queued. Call from application context.
